# Findings draft part 3 (emulator-proven money/scope/payment findings)

Evidence logs: logs/audit-03-money-scope.txt, logs/audit-04-payments.txt (suites 03, 04). All run on the Firestore/Auth emulators with a `demo-*` project; gateway "signatures" use the emulator's throw-away test secret.

## Critical / release blockers
- V-01 [Critical, CONFIRMED MS-01] `DELETE /client/video/deleteVideoRecord?videoId=<own video>` (client/video.controller.js:4823-4875; route requires only ownership of the *single* id checked by `requireOwner`) calls `Video.find({_id:{$in:videoIds}})`; the shim drops `$in`, so the handler iterates **every video on the platform** and runs `Video.deleteOne` + storage cleanup for each. Seeded 3 videos owned by 3 users → user 1 deleting its own video left 0 videos. Any registered user can wipe all video records. (Same root cause as D-01; admin `deleteVideoReport` DL-03.)
- PAY-1 [Critical, CONFIRMED PY-02] `POST /client/coinplan/createCoinPlanHistory` (coinplan.controller.js:49-166) verifies only an HMAC over `orderId|paymentId`; it never checks that the order exists in `paymentTransactions`, belongs to the caller, or was created for the requested `coinPlanId`/amount. Combined with `processRazorpayPayment` (PY-04: creates gateway orders for any client-chosen `amount`), a ₹1 payment can be redeemed for the most expensive plan (emulator: 1,100,000 coins = ₹11,000 credited for an unrelated proof).
- PAY-2 [Critical, CONFIRMED PY-03] The same endpoint's replay protection is a non-atomic `findOne({paymentId})` followed by the credit after the response is sent: 6 parallel requests with one proof credited 600 coins for a 100-coin payment.
- PAY-3 [Critical, CONFIRMED PY-01] `POST /client/premiumPlan/createHistory` (premiumPlan.controller.js:28-120) activates any premium plan for any signed-in user with **no payment or proof** (`isPremiumPlan:true`, plan benefits, history rows).
- PAY-4 [High, CONFIRMED MS-03] Coins bought with real money are indistinguishable from reward coins: `coinToAmountConverter` (client/withDrawalRequest.controller.js:71-178) and `reserveWithdrawal(convertShortfall)` convert any `coin` balance to withdrawable ₹ at 100:1; `purchasedCoin` is tracked but never excluded. PAY-1..3 therefore chain into cash-out; independently it is a ₹-in/₹-out channel (money-laundering/stolen-card cash-out) and plans with `extraCoin` bonuses can be arbitrage.
- P-01 / P-02: see findings-draft-2 (public endpoints leak password hashes/emails/FCM tokens; guessable ids).
- D-01: see findings-draft (operator filters dropped).

Admin withdrawal list with a date range returned 0 of 1 rows. Nine call sites: client/monetizationRequest:172, admin/monetizationRequest:40, admin/premiumPlan:133,252, client/withDrawalRequest:335, admin/videoComment:146, admin/withDrawalRequest:59, admin/report:41, client/userWiseSubscription:380.
