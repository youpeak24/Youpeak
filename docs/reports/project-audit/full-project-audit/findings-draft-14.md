# Findings draft part 14 — deployed web observations, deep links, accessibility, admin UI sweep

Evidence types: [D] real deployed site, GET/navigation only, no login; [E] local emulator stack with demo data (admin dev server on :3055, backend :5055); [S] static.

## Deployed web (consumer https://www.youpeak.app, admin https://admin.youpeak.app) [D]
- WEB-0 [Pass] At 1920, 1366, 768 and 390 px (real viewport emulation over the DevTools protocol, not a window resize) the admin sign-in page and the consumer onboarding → "Let's you in" screens render with **no horizontal overflow**; the consumer layout switches from a phone column (≤768) to a branded split screen (≥1366); no failed requests; consumer console shows only library debug lines (Firebase init) and no app logging before sign-in. Screenshots: `screenshots/admin-login-*.png`, `consumer-home-*.png`, `consumer-onboarding-*-step*.png`.
- DL-1 [High, functional — referrals and shared links] **Universal/App Links cannot verify.** (a) Android intent filters and the iOS `applinks:youpeak.app` entitlement use the apex host `youpeak.app`, but `https://youpeak.app/.well-known/assetlinks.json` and `.../apple-app-site-association` answer **308 → www.youpeak.app** (Android verification requires a direct 200; a redirect fails). (b) The file served on www for iOS is the empty stub `{"applinks":{"apps":[],"details":[]}}`, so iOS universal links cannot work at all. (c) The iOS bundle identifier is still the template value `com.live.metube` while Android is `com.YouPeak.Live1`. Effect: partner referral links and shared video links open the browser/web app instead of the installed app, and the referral code is only carried through Branch (mobile) or the web app's own path handling. Fix: serve both files from the apex with 200 (or make `www` the only host in the manifest/entitlement), publish a real AASA with the team id + bundle id, align the bundle id. Test: `curl -I` both hosts; Google Digital Asset Links API; Apple AASA validator.
- DL-2 [Medium, compliance] `https://www.youpeak.app/privacy` and `/terms` return the Flutter shell and render the **sign-in screen** (screenshot `consumer-deeplink-privacy-390.png`); there is no privacy-policy or terms page at those URLs. `robots.txt` and `sitemap.xml` also return the HTML shell with 200 (soft-404). Play Console/App Store review and DPDP/IT-Rules notice requirements need a reachable policy URL. (Whether the policy lives elsewhere — e.g. in-app Settings or `youpeak.in` — was not verifiable; `youpeak.in` returns 404, DEP-5.)
- DL-3 [Low] Every path (including unknown ones) returns 200 + the shell; unknown deep links show the onboarding/sign-in screen, never a 404 or "link not found" state.
- WEB-1 [Low] All consumer assets, including the 6.4 MB `main.dart.js` (1.78 MB with brotli), are served `Cache-Control: public, max-age=0, must-revalidate`; fingerprintable CanvasKit/asset files could be cached `immutable`. Startup on slow links relies on revalidation round-trips.
- A11Y-1 [Medium] Flutter web builds its semantics tree only after the user activates the hidden "Enable accessibility" placeholder: at load, `flt-semantics-placeholder` is present and `flt-semantics` nodes = 0, so the page body has **no readable text** for a screen reader or text-extracting tool until that placeholder is activated (whether that placeholder is reachable and announced by a keyboard / screen-reader user was not tested). Combined with the forced 0.8 text scaler (FL-16) the web app does not honour browser/OS text-size settings. Fix: call `SemanticsBinding.instance.ensureSemantics()` on web, remove the forced scaler, and test with NVDA/VoiceOver. (Mobile TalkBack/VoiceOver was not testable here — **BLOCKED: no device**.)
- AFE-18 [Medium, supply chain] The admin shell (`admin/frontend/public/index.html`) loads **executable third-party code without Subresource Integrity**: jQuery from `code.jquery.com`, `bootstrap4-toggle` from `cdn.jsdelivr.net/gh/gitbrent/...@3.6.1` (a GitHub-backed, mutable path), plus bootstrap-icons and Font Awesome CSS. Only Bootstrap CSS/JS carry `integrity`. These scripts run on the origin that stores the super-admin JWT in `sessionStorage` (AFE-2), and the site sends no CSP (DEP-2). Fix: self-host or add SRI hashes, add a CSP. Also: `<title></title>` is empty (WCAG 2.4.2), and the password input is not inside a `<form>` (Chromium warning; Enter-to-submit and password-manager semantics).

## Admin UI sweep on the local demo stack [E]
Method: `audit-tests/cdp-admin.cjs` logs in with the documented demo fixtures and opens every route each role may open at 1920/1366/768/390 (184 role/route/width views: Super Admin 33 routes, District Franchise 6, Digital Partner 7); records horizontal overflow, console/page exceptions, HTTP ≥ 400 answers and blank pages. `audit-tests/cdp-admin-states.cjs` checks role redirects, unknown routes, offline, invalid token, back navigation and refresh. Screenshots under `screenshots/admin-*/`.
- AFE-22 [Pass] 184 of 184 views loaded real content: **no page overflowed horizontally, no JS exception, no console error and no API answer ≥ 400** were recorded (demo data only; the seeded empty-state endpoints return 200). A franchise login that opens `/admin/userTable` by URL is redirected to its dashboard before any call is made; an invalid/expired token returns the user to `/login` (verified after reload); offline shows "Dashboard unavailable. Couldn't load your…"; browser Back returns to the previous page; a refresh on a deep page keeps the session (sessionStorage).
- AFE-19 [Low] A Super Admin who opens an unknown admin URL (e.g. `/admin/doesNotExist`) gets an empty content area — no 404 page and no redirect (franchise/partner logins are redirected home).
- AFE-20 [Low, data visualisation] Dashboard "Data Analytics" chart (`mainDashboard`): the x-axis is categorical, so unevenly spaced dates (08-01, 08-05, 08-15 … 08-30, **10-06**) are drawn equidistant; lines are smoothed with Bézier curves, producing overshoot peaks between sparse points that do not exist in the data; the y-axis has no labels/scale. At 1366 px the "Total User Activity" donut is wider than its card and is clipped on the right edge (screenshot `admin-super/mainDashboard-1366.jpg`); it is fine at 1920/768/390. The first heading element on the dashboard is the stat value "7" (heading misuse).
- AFE-21 [Low, accessibility] Controls without an accessible name (no aria-label/title/text/label/placeholder) per page, at 1366 px: Platform Config → Peak Boost 35, Ad Credits 20, Partner Program 17, Tasker 14, Safety 11; Users 9, Videos 8, Bites 11, Settings 11; icon-only Pay/Decline buttons on Withdrawals (AFE-7). Colour-contrast and keyboard-focus order were not measured (**not tested**).
- AFE-24 [Info] The Peak Boost config page exposes a third "Referrer share" field beside creator 80 % / platform 20 % (value 0 in the demo); the Peak Boost spec (RC-9) defines only 80/20, so any non-zero referrer share would change the documented split.
- AFE-23 [Info] Cross-panel observation on the demo data: the District Franchise dashboard text still advertises the V9 referral workflow with "20 % of their tasker earnings … and ₹2.5 instantly" for the partner (RF-1; V9 §1.5 does not define a passive commission), and a commission row status renders as "Paid —" (stray dash).
