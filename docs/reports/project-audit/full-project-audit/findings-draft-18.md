# Findings draft part 18 — cross-privilege XSS and cache behaviour

## XSS-1 [High, CONFIRMED server side on the emulator; browser sink confirmed by code read, not executed]
A District Franchise login can plant HTML in a Digital Partner's email that is later rendered as markup in the Super Admin's browser.
- Evidence:
  - Server: `partnerNetwork.service.js:30` validates e-mail addresses with `EMAIL_RE = /^[^\s@]+@[^\s@]+\.[^\s@]+$/`, which accepts `<img/src=x/onerror=alert(document.domain)>@a.bc` (no whitespace, one `@`, a dot). `audit-tests/suites/10-xss-sink.cjs` XSS-01: `POST /admin/franchisePortal/partners/create` with that e-mail returned `status:true` (partner created, app account created); XSS-02: `POST /admin/digitalPartner/regeneratePassword` (Super Admin) returned `portalCredentials.email` verbatim, markup included (logs/audit-10-xss-sink.txt). Real Firebase Auth may refuse such an address when the app account is created through `createEmailPasswordAccount`; the emulator accepted it, and a franchise can also "link" an existing app user whose stored e-mail was typed at sign-up (P-03: no e-mail verification on e-mail/password sign-up).
  - Browser sink: `admin/frontend/src/Component/Pages/DigitalPartner/PartnerDetail.js:84-88` calls `Swal.fire({ html: \`Email: <b>${res.data.portalCredentials.email}</b><br/>Password: <b>…</b>…\` })` — SweetAlert renders `html:` as HTML, unescaped. Every other dialog in the SPA passes user text through `text:` (escaped) and no `dangerouslySetInnerHTML` exists.
- Trigger: a Super Admin opens the planted partner (`/admin/partnerDetail?userId=…`, shown in the franchise and partner lists) and presses "Generate new panel password" — a plausible support action.
- Impact: script runs on `admin.youpeak.app` in the Super Admin's session: reads the 7-day admin JWT and the shared key from `sessionStorage` (AFE-2), and can call any admin API (withdrawal approvals, platform config). The site sends no CSP (DEP-2), so nothing limits it. It crosses a privilege boundary (franchise → super admin), which the otherwise strong scope isolation (AZ-01..11) does not cover.
- Fix: escape the values (`Swal.fire({ title, text })` or `textContent`), validate e-mail with a stricter allow-list (and reject `<`, `>`, quotes), add a CSP to the admin host, keep the JWT out of `sessionStorage`.
- Verification: rerun suite 10 (XSS-01 must fail closed) and add a Cypress/Playwright check that the dialog text shows the literal characters.

## CACHE-1 [Low] Settings propagation window
`global.settingJSON` is refreshed from the Firestore `settings` document with a 5-minute TTL per serverless instance (HANDOVER §2: `settingsMiddleware`); admin saves call `loadSettings(true)` only on the instance that served the save. Different Vercel instances can therefore serve different values (coin caps, minimum withdrawal, payout limits) for up to five minutes after an admin change, and the app mirrors `system_configs/*` through a live Firestore listener while the server enforces from its own copy. Mismatch is possible during the window (the app may show a limit the server no longer applies). Not reproduced; derived from the loader design.
