# Findings draft part 4 (panels, partner/franchise flows, requirement gaps)

## Panel / cross-panel
- LB-1 [High, code] `admin/localBusinessAd.controller.js:46-118` — approving a partner-submitted local business ad immediately credits the Digital Partner **50 % of the self-declared `adBudgetInr` as wallet coins** (and writes a 30 % franchise commission row). No advertiser payment, no ad-credit debit and no upper bound on `adBudgetInr` (client + partner-portal `submit` only require > 0). `claimOnce("commissionCredited")` is flipped before the payouts, so a failure afterwards leaves the ad stuck `PENDING_REVIEW` with the flag set ("already being processed"). The 50 % direct share has no source document (only the 30 % district margin is documented, DOC-20260826-WA0000).
- LB-2 [Medium] `client/localBusinessAd.recordImpression/recordClick` are callable by anyone with the public key and unlimited → impression/click counts shown in partner/admin reports are not trustworthy.
- CP-1 [Medium, cross-panel] Three different numbers for a partner's "earnings": consumer app `getDashboard.totalEarningsInr` = released stage coins only (partner.controller.js:68); partner portal `earnings.referralInr` = `user.referralRewardCoin` (includes free-tier bonus, paid-tier %, tasker-commission 20 %); super-admin `digitalPartner.report.referralEarningsInr` = `user.referralRewardCoin × rate`; franchise summary `rewardInrReleased` = stage releases. The same partner shows different amounts per panel.
- CP-2 [Medium] `digitalPartner.report` counts `licenseFeePaid` (including franchise self-reported, unverified fees) as `licenseRevenueInr`; partner-report ranges use `new Date("YYYY-MM-DDT00:00:00")` in server-local time (UTC on Vercel) rather than IST → period boundaries shift by 5.5 h.
- DS-1 [High, requirement] No consumer path ever stores `state`/`district` on a user (only `createEmailPasswordAccount` for franchise-created partners; the Flutter app has no location/district input — pubspec has no location plugin, only `geocoding`). `resolveAgency` therefore returns null for normal consumers, so **no District Franchise commission rows are ever generated for consumer unlocks, passes or ad revenue**, and `agencyReport.totalUsers` (users with `district == agency.district`) is ~0. Requirements: Developer quotation §2.1(2) "geographical location tracking … configurable radius", §2.2 geofenced agency management, download/video/ad analytics by region, District Partner commission chart.
- AC-1 [High, requirement] Ad credits are never consumed: `adCreditsBalance` is granted (Starter Pass `adCreditsGranted`, partner licence) and displayed but no endpoint debits it (grep: only `commission.controller.js` reversal subtracts). TRS Module D ("deduct usage … when ads are served") and V9 §1.1 ("Ad Credits to promote user/creator content") are not implemented; video promotion is bought with money (`fulfilVideoPromotion`), not credits.
- AG-1 [Low] District franchise uniqueness (`assertDistrictFree`) is check-then-create; `uniqueCode` loops with `findOne` (non-atomic).
- SC-1 [Medium] Scope enforcement positives (verified by code): admin.middleware denies AGENCY_ADMIN / DIGITAL_PARTNER_ADMIN everything except their allow-list; franchise/partner controllers scope by `req.agencyId` / `req.partnerUserId` set from the DB admin record; `loadScopedPartner` re-checks agency ownership. Residual: allow-list uses `req.originalUrl` (case-sensitive, exact paths) and Express routing is case-insensitive — fails closed; `/api/admin/...` prefixed calls from restricted roles are denied (functional, see UI checks).
