# Findings draft part 17 — late findings (scripts, legacy purchase code, creation flow, accessibility metrics, defaults)

## Operational scripts
- SCR-1 [High risk if run, process] `DB/execute_import.js`, `DB/fix_video_urls.js`, `DB/enrich_videos_db.js`, `DB/execute_*_import.js` import `functions/backend/util/firestoreDb.service` directly and write to whichever Firebase project the local credentials point to; the environment guard that protects the server (`util/localServerGuard.js`, `ALLOW_LIVE_FIREBASE`) is only called by `server.js`, so these scripts have **no guard**. `execute_import.js` loops over every `DB/*.json` (including `users.json` and `admins.json`, which are tracked with plaintext passwords) and `create()`s each document with its seed id; `fix_video_urls.js` rewrites every video's `videoUrl`/`videoImage` to `${r2PublicDomain}/videos/<id>.mp4` and `thumbnails/<id>.jpg`. Run by mistake with the production service account (it exists on the developer machine, SEC-1), they would overwrite production users/admins/videos with demo data. Fix: call the guard at the top of every script, require an explicit `--i-know-this-is-production` flag, move seed data out of the repo or hash the passwords.

## Mobile purchase code (legacy template)
- IAP-1 [Medium] `core/payment/in_app_purchase/in_app_purchase_helper.dart` is the template's Apple/Google subscription helper and still runs on every phone that opens the coin payment screen (`getAlreadyPurchaseItems` → `restorePurchases`, `completePurchase`). It verifies iOS receipts **from the device** against Apple's deprecated `verifyReceipt` endpoint with `if (2 == 2) { sandbox URL }` (always sandbox) and Dio timeouts of `Duration(microseconds: 5000)` (5 ms, not 5 s), so verification cannot succeed in production; results are written to local flags (`Preference.isPurchasePremium`) that nothing in the app reads, and `onSuccessPurchase` in the coin screen is empty. It never calls the backend. Consequence: if a store purchase is ever completed through this path the user is charged and nothing is delivered (FL-1); on restore, pending purchases are "completed" silently. Fix: delete it, or implement purchase → server receipt validation (Play Developer API / App Store Server API) → entitlement.

## Account / channel creation flow
- CHN-1 [Medium, suspected — needs a UI run] `EditProfileApi` sends `channelType: AppSettings.channelType.value` with every profile edit and the backend accepts it (`userFirestore.controller.js:454-456`). `AppSettings.channelType` is a global `1.obs` that is only assigned in the (commented-out) create-channel radio buttons, so after an app restart a creator whose channel was set to type 2 (paid/private) who edits their name or phone resets it to type 1 (public). I found no code that initialises it from the profile.
- FL-22 [Low] Several API clients build query strings by interpolating raw user text without encoding: `search_api.dart` (`searchString=$searchString`), `play_list_get_with_search_api.dart` (`search=$search`), referral-code apply, grievance track. A search containing `&`, `#`, `+` or `%` is truncated/misparsed (e.g. "Tom & Jerry" searches for "Tom "). Use `Uri.https(host, path, queryParameters)`.
- FL-23 [Low] Comment, reply, like/dislike, share-count and report calls (`create_comment_api.dart`, `create_reply_api.dart`, `like_dislike_api.dart`, `like_dislike_comment_api.dart`, `share_count_api.dart`) return `void` and ignore the response: a refusal (SECURITY_LOCK, daily cap, blocked user, 401) is invisible to the user and the optimistic UI keeps the like/comment shown.
- FL-24 [Medium] Bites audio-merge race: `create_short_controller.dart` removes the recorded audio and merges the chosen sound with `FFmpegKit.executeAsync(...)` (returns immediately) and then waits with two fixed `Timer(Duration(seconds: 10))` before opening the upload screen (lines ~135-138). FFmpeg completion is never awaited or checked (`returnCode` is read but unused): on a slow phone the merge is not finished after 10 s and an empty/partial file is uploaded; on a fast phone the user waits 20 s needlessly. The recorder also hard-codes a 30 s maximum while the server limit is `durationOfShorts` (60000, unit unclear — VID-1).
- FL-25 [Low] `check_channel_name_api.dart` sends the channel name as the **body of a GET request** (`http.Request('GET')` with `request.body`). Browsers (the Flutter web build uses XHR/fetch) drop GET bodies, so on the web the "channel name already in use" check reaches the server without a name; server handlers and proxies may also drop it. Use query parameters.

## Accessibility and error-handling metrics (static scan)
- A11Y-2 [Medium] Flutter source: 318 `GestureDetector(` + 20 `InkWell(` tap targets versus 16 `Semantics(`, 15 tooltips and 12 `semanticLabel`s — nearly every icon-only control (images inside `GestureDetector`) has no accessible name for TalkBack/VoiceOver/screen readers; with the web semantics tree off by default (A11Y-1) the consumer app is effectively unusable with assistive technology. Android `fontScale` is overridden (0.8, FL-16).
- FL-26 [Info] Flutter static metrics: 459 Dart files / 81,785 lines; 388 force-unwrap `!.` expressions; 14 empty `catch` blocks and 166 catches that only log; 104 HTTP calls (101 without timeout, FL-18); 55 `Get.dialog(LoaderUi…)` loaders (closing them depends on every path calling `Get.back()`; not verified path by path); 54 TODO/FIXME/HACK markers; 165 `print`/`debugPrint`; 3 of 7 `Image.network` have an `errorBuilder`. Analyzer: 0 errors, 84 warnings, 814 infos.
- AFE-25 [Medium] Admin SPA static metrics: 189 JS files / 34,838 lines; 169 `.catch(` handlers of which 107 only `console.log/error` (no toast, no state change); 28 direct axios calls plus a fetch wrapper; 19 `MM/DD/YYYY` date formats; 70 `console.log` calls; one automated test file (`apiError.test.js`, 4 tests) for the whole SPA. The silent-failure pattern is why a failed load shows an empty table (AFE-14).

## Defaults and stale deployments
- DL-2b [Medium] The default `privacyPolicyLink` and `websiteUrl` in `functions/backend/setting.js:27,283` are `https://youpeak-9ff65.web.app`. That host serves a **stale, unbranded Flutter web build** ("A new Flutter project", `<title>youpeak</title>`, no policy text). The in-app Privacy Policy screen (`privacy_policy_web_view.dart`) loads exactly this URL unless the production settings document overrides it (not readable by me — BLOCKED). HANDOVER.md says Firebase Hosting is not used, yet the default hosting site is live and publicly serving an old build (possible old API/keys inside it; unreviewed). Fix: publish the real policy and terms on `youpeak.app`, update the setting, and delete or redirect the old hosting site.
- DL-4 [Info] Public association files are served through the API (`youpeak/web/vercel.json` rewrites `/.well-known/*` to `https://api.youpeak.app/.well-known/*`); the Android `assetlinks.json` lists package `com.YouPeak.Live1` with one signing-certificate fingerprint (public information) and the iOS file is empty (DL-1).
