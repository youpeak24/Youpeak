# Findings draft part 9 — deployed observations (read-only, 2026-10-06) and Flutter client

## Deployed observations (real production; GET/HEAD/OPTIONS or deliberately-rejected requests only)
- DEP-1 DNS/hosting: `youpeak.app`, `www.youpeak.app` (Flutter web, `flutter_bootstrap.js`), `admin.youpeak.app` (React admin, `main.20080291.js`) and `api.youpeak.app` all resolve to Vercel and answer 200 over HTTPS; `youpeak.app` 308-redirects to `www`. The domain split described in DEPLOYMENT.md is live (the earlier report said admin/api had no DNS; that is no longer true). `GET api.youpeak.app/api/ping` → `{"status":true,"service":"youpeak-api","dependenciesChecked":false}` (liveness only, not dependency health).
- DEP-2 [Medium] Only `Strict-Transport-Security` is sent by all four hosts. No `Content-Security-Policy`, `X-Frame-Options`/`frame-ancestors`, `X-Content-Type-Options`, `Referrer-Policy` or `Permissions-Policy` on the admin panel (clickjacking / XSS blast radius) or the consumer app.
- DEP-3 [Medium, CONFIRMED] Production API CORS: a preflight with `Origin: https://evil.example` returned `204` with `Access-Control-Allow-Origin: https://evil.example` and `Access-Control-Allow-Credentials: true` (reflects any origin). Auth is by bearer header so CSRF is limited, but any website can call the API from a visitor's browser if it has the token/key; brief asked for CORS review.
- DEP-4 [High, CONFIRMED] `POST /payment/webhook/razorpay` (bogus body) → `400 {"message":"no_webhook_secret"}`: no Razorpay webhook secret is configured in production (env or settings). Gateway webhooks cannot be verified, so order fulfilment depends only on the app's client-side `verify` callback; a paid order whose app closes before `verify` is never fulfilled automatically (no scheduled gateway reconciliation exists; only manual admin retry with a payment id).
- DEP-5 [High, CONFIRMED] `https://youpeak.in/` (the default `membershipPortalUrl`; every "Buy pass / Starter Pass / Creator VIP / Digital Partner licence" button in the app opens `https://youpeak.in/?plan=…&uid=…&source=app`) returns **HTTP 404** (resolves to Vercel, no page); `partners.youpeak.in` does not exist. Nothing in this repository implements that portal or calls `createOrder(purpose: "tier_upgrade" | "digital_partner_license")`, so the V9 "Option B instant Starter Pass", Creator VIP passes and the Partner licence are **not purchasable by any user today**.
- DEP-6 Protected endpoints behave as designed in production: `client/setting` without key → 401; `cron/daily` → 401; `internal/fingerprint/queue` → 401; `/admin/login` GET → `{login:true}`.
- DEP-7 [Info] Anonymous Firestore REST list requests (status code only) for `users`, `admins`, `paymentTransactions`, `withDrawRequests`, `settings` and `system_configs` all returned 403, i.e. the database is not open to the public. The repository rules allow public `get`/`list` on `system_configs/*`; a 403 on that collection suggests the deployed rules differ from `firestore.rules` (or listing is blocked) — reading the doc itself was refused by the permission policy, so **BLOCKED: confirm deployed rules with `firebase deploy --only firestore:rules` dry-run/console**. Firebase Storage anonymous listing returned 400 (not usable as evidence).
- DEP-8 [Info] Grievance officer data served publicly: officer name "Grievance Officer", e-mail `grievance@youpeak.in` (domain `.in`, product on `.app`), phone empty — IT Rules 2021 require named officer and contact details; placeholders are still in production settings.

## Flutter client (partial — in progress)
- FL-1 [High, store-compliance] Coins and premium plans are bought in the Android/iOS app through Razorpay (`coin_payment_view.dart`, `payments_view.dart`; shown when `razorPaySwitch`/`razorpayIosEnabled`). Digital goods in a Play/App Store app must use platform billing (Google Play Billing / Apple IAP); the same screen lists Google/Apple "Pay", Stripe, PayPal, Paystack, Cashfree, Flutterwave rows but every non-Razorpay choice ends in the toast "payment method coming soon", and the IAP success callback is an empty method (`onSuccessPurchase(PurchaseDetails) {}`) so a platform purchase would be charged without delivering coins.
- FL-2 [Medium] Architecture brief (Architecture Split / Final Blueprint) says no joining fees or financial logic inside the store app; the app contains coin purchase, premium purchase, video promotion purchase, withdrawals, Peak Boost and a partner dashboard, while pass purchases are redirected to a portal that does not exist (DEP-5).
- FL-3 [Low] Shipped client calls `client/coinplan/createCoinPlanHistory` only through `PurchaseCoinPlanApi`, which sends no payment proof (so it is rejected server-side); the legacy exploitable endpoints (PAY-1..3) are not used by the current app but remain reachable by anyone with a token.
