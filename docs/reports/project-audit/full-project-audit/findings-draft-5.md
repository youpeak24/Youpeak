# Findings draft part 5 (collections, feeds, subscriptions)

Evidence: logs/audit-05-collections.txt (suite 05, emulator).
- CF-01 [High, CONFIRMED] The same logical collection is addressed by up to three names: the Mongoose-shim model name (`WatchHistory`, `VideoComment`, `UserWiseSubscription`, `LikeHistoryOfVideo`, `SaveToWatchLater` — written by `Model.create`), the lower-case plural used inside aggregate `$lookup` (`watchhistories`, `videocomments`, `userwisesubscriptions`, `likehistoryofvideos`, `savetowatchlaters`) and, for subscriptions, camelCase direct `db.find("userWiseSubscriptions")` (user.controller.js:269). `normalizeCollectionName` (firestoreDb.service.js:107-155) only maps some names. Result on a clean database: after a real subscribe call, feed `isSubscribed=false` and `detailsOfChannel.totalSubscribers=0` (CF-02); after a WatchHistory row is written, feed `views=0` (CF-03). Comment counts, like state, watch-later flags and unlock/subscription gating in the ~25 feed pipelines are affected the same way. Production impact depends on what names the live data actually uses (not verifiable without credentials) — a split between migrated and new rows is likely.
- CF-04 [High, CONFIRMED] `GET /client/video/shortsOfUser` (video.controller.js:714-899) computes the list but never calls `res.json` on success; only the catch block responds. The request hangs until the 30 s function limit. (Check whether the Flutter app calls it — see client section.)
- CF-05 [Medium, CONFIRMED by code search] Paid channel subscriptions store `expiryDate` (+1 month) but nothing ever reads it: `withholdLockedPlayback.js`, feed `isSubscribed`, `subscribedUnSubscibed` all treat any subscription row as permanent → one month's fee buys permanent access.
- SUB-1 [Medium] `subscribedUnSubscibed` (paid channel): `spendBalance` debits the subscriber, then subscription row, owner credit and two history rows are written in `Promise.all` outside a transaction; a partial failure leaves the user charged with no subscription. The owner receives 100 % of the fee (no platform split configured for subscriptions).
- SUB-2 [Low] Channel identity is inconsistent: `createVideo` assigns `channelId = uuid.v4()` for new channels (video.controller.js:435) while `user.update` sets `channelId = userId` (user.controller.js:181-183) and several handlers (`detailsOfChannel`, `withholdLockedPlayback`) treat channelId as the owner's user id.
- VID-1 [Medium] `createVideo` trusts the client-supplied `videoTime` for the Bite duration limit (`settingJSON.durationOfShorts` default 60000 compared with `parseInt(videoTime)` — unit unclear: if seconds the limit is ≈16.7 h, i.e. no limit); Cloudflare metadata is not consulted.
