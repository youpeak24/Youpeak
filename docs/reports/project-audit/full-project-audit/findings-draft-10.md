# Findings draft part 10 — admin React frontend (Super Admin / District Franchise / Digital Partner panels)

Method: static read of Admin.js, App.js, AxiosInterceptor, PrivateRoute, Login, Sidebar, AwsFunction, PartnerPortalPages, PartnerWallet, FranchisePartners, WithDrawRequest/WithDrawDetails and withdraw.action; production build (`CI=true npm run build`) and a cross-reference of every backend `/admin/*` route against strings in the SPA. Visual/responsive checks: see responsive-and-ui.md (blocked items listed there).

## Build
- AFE-0 [Pass] `npm run build` compiled successfully (exit 0). Main bundle 836 kB gzip (CRA warns "significantly larger than recommended"; no code splitting; every page is imported eagerly in Admin.js).

## Role handling (client side is only UX; the backend allow-list is the control — AZ-01..11 confirmed it)
- AFE-1 [Info, GOOD] `Admin.js` renders nothing and redirects before mount for pages outside `ROLE_PAGES` (franchise: 7 pages, partner: 7 pages), so a franchise/partner login never fires super-admin API calls from the UI; the backend independently returns 403 for them.
- AFE-2 [Medium] Admin JWT, role and admin profile live in `sessionStorage` (`token`, `admin`, `key`, `isAuth`) and `PrivateRoute` trusts `sessionStorage.isAuth`. Any XSS in the SPA (no CSP is served — DEP-2) can exfiltrate a 7-day super-admin JWT. `dangerouslySetInnerHTML`/`eval` were not found in `src` (grep), which lowers likelihood. Fix: CSP + httpOnly cookie or short-lived token with refresh.
- AFE-3 [Low] `sessionStorage.dialogueData` re-opens the last dialog (including the Withdrawal "pay" dialog with payout details) after a page refresh; the stored object contains the full request row (payout account details) in clear text in the browser storage.

## Withdrawal workflow (Super Admin) — `WithDrawRequest.js`, `WithDrawDetails.js`, `withdraw.action.js`
- AFE-4 [High, money] "Accept" is described as paid: backend message "Withdrawal request accepted and paid to particular user" and the push "being processed", but nothing pays: no gateway call, no UTR/bank reference field, no proof upload. The dialog is a two-button modal (Close / Accept) with no confirmation of amount, no payout-reference capture and no "mark paid on date". The wallet is settled when an admin clicks Accept, whether or not money was actually sent, and the audit trail has no external reference. (Same root as AD-4 — payout gateway and midnight settlement are not implemented.)
- AFE-5 [Medium] `acceptRequest`/`declineRequest` show a toast only when `res.data.status` is true; on `status:false` (already accepted, insufficient balance, lock held) or a network error they `console.log` and do nothing visible, so the admin sees the dialog close with no result and cannot tell whether the payout was recorded. Re-clicking is safe server-side (`claimOnce`), but the UI gives no feedback.
- AFE-6 [Low] `declineRequest` builds `...&reason=${reason}` without `encodeURIComponent`; a reason containing `&`, `#` or `%` is truncated/garbled in the stored reason shown to the user; reason also travels in the URL (access logs).
- AFE-7 [Low] The "Payment Gateway" and "Request Date" fields in the accept dialog are editable inputs with placeholder "Enter Symbol" (copy-paste artifact) and show a raw ISO date; edits are discarded. Request dates in the table use `MM/DD/YYYY` while the product is India-first. Pay/decline buttons are icon-only `<button>` with no `aria-label` or title (accessibility).
- AFE-8 [Low] Payout details are shown split on the first `:`; a value that itself contains a colon (UPI deep link, URL) is truncated in the dialog (`data.split(":")[1]`).

## Partner / franchise panels
- AFE-9 [Info, GOOD] Partner wallet page validates minimum convert / withdraw, blocks a second pending request client-side, and displays the server's message; the server remains the authority (I read `partnerPortal.controller.js` earlier; my audit suites did not drive the partner wallet routes — only the repo's `06-withdrawals` suite exercises withdrawal rules, on the app path). The first-withdrawal minimum (₹100) vs later minimum (₹500) comes from the server.
- AFE-10 [Medium] Partner Wallet "Convert" preview uses `rate = minCoinForCashOut || 100`; the app wallet, the admin Platform Config and `partnerPortal` use different sources for the rate (CU-1..3). If the setting is changed the preview and the server result can differ by the stale client value.
- AFE-11 [Low] `PartnerWallet`/`FranchisePartners` etc. hide errors behind generic toasts ("Couldn't load your wallet") and, for the wallet, render `null` after a failed first load (blank panel, no retry button). `usePartnerDashboard` has no retry or offline state; a 403 for a suspended partner is shown as a toast, not as the "inactive partner" page, because `NotActivePartner` is shown only when the call succeeds with `isDigitalPartner === false`. (The axios interceptor clears the session on `ACCOUNT_DISABLED`, which mitigates it.)
- AFE-12 [Low] Franchise Partners table filters/search run client-side over the full list returned by the API; the endpoint is not paginated, so a franchise with thousands of partners loads everything on every action (`load()` after each status change).
- AFE-13 [Info] Partner/franchise pages use `Loading…` text rows and `EmptyRow` empty states consistently; Super Admin tables use skeletons. No page hides a failed call behind an infinite skeleton except `getWithDrawRequest`, whose `.catch` only logs (AFE-14).
- AFE-14 [Medium] Many redux actions (`getWithDrawRequest` and other `store/*/*.action.js` that use `apiInstanceFetch`) only `console.error` on failure. The spinner is cleared correctly (`apiInstanceFetch` uses `.finally(closeSpinner)`; my first reading that the skeleton would hang was wrong and is withdrawn), but the table then shows an empty list with no error, so an outage or a 500 is indistinguishable from "no withdrawal requests" — risky on a money screen.

## Upload helper (`util/AwsFunction.js`)
- AFE-15 [Medium] Video uploads PUT directly to a presigned URL from `admin/file/direct-upload-url`; no client-side size/type limit and (server-side) no size condition on the presigned PUT (ME-2). Images go through `admin/file/upload-file` multipart (server buffers in memory on Vercel — 4.5 MB request cap on Vercel functions; larger images fail with a platform 413 that the SPA reports only as a generic upload error). The helper opens/closes the global loader correctly (`finally`).
- AFE-16 [Low] Upload progress for videos is faked (0 → 100); `fetch` PUT gives no progress. Cosmetic.

## Route coverage (backend ↔ SPA)
- AFE-17 [Info] About 50 of the 185 `/admin/*` API routes have no direct caller in the SPA (two static matchers gave 51 each with slightly different members; templated URLs such as `admin/platformConfig/${section}` were checked and are used — my first list wrongly included `PATCH platformConfig/:section`, now removed). The groups that held in both runs (full first list in route-inventory.md): advertise/create, coinplan/delete, contact/*, FAQ/*, language/* (the SPA has no language screen), contentModeration/rescreen, copyrightModeration/manualFlag, creatorFunding/list|forceCancel, grievance/list|resolve, localBusinessAd/list|approve|reject, mediaAudit/report, membershipTier/seedDefaults, payment/list|markPaid|reconcile, setting/applyEconomyDefaults|publishSystemConfigs, translation/* (4), user/isActive, user/paymentWebhook, videoComment/*. Consequences, each with a requirement impact:
  - There is **no UI to review grievances** (IT Rules 2021 workflow) or to approve/reject **Local Business Ads** from Super Admin (the only SPA caller is the partner's `localBusinessAd/submit`; approval needs the API directly) — the product cannot be operated end-to-end from the panel.
  - **No UI for manual payment reconciliation / mark-paid** while the Razorpay webhook secret is not configured (DEP-4), so a stuck payment can only be fixed by calling the API manually.
  - No UI for the creator-funding list/force-cancel, media audit report, copyright manual flag and content re-screen.
  - Translation/language management has backend routes but no screen, and the routes crash anyway (SM-3).
  (Caveat: static string match; a route built by string concatenation would be missed. A second case-insensitive grep for grievance, language/, payment/list, payment/markPaid, creatorFunding, mediaAudit, translation/, videoComment/getComment, contact/ and FAQ found no caller; localBusinessAd matched only the partner submit call.)
