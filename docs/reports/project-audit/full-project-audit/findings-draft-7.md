# Findings draft part 7 (monetisation, moderation, products with no delivery)

- MON-1 [High, code] Admin approval of a monetisation request (`admin/monetizationRequest.controller.js:141-156`) sets `totalWithdrawableAmount: 0, totalEarningAmount: 0` on the user and `WatchHistory.deleteMany({videoChannelId})`. `totalEarningAmount` is the *withdrawable wallet* shared by tasker coin conversions, referral/partner payouts and creator earnings, so approving a creator zeroes any cash the same person earned elsewhere (reserved amounts are left, producing reserved > available), and erases the channel's view history. The decline branch was already fixed for exactly this copy/paste issue.
- MON-2 [Medium] `fulfilTierUpgrade` sets `isMonetization:true` for *any* paid tier including Tasker passes (payment.controller.js:499,511), bypassing the admin monetisation criteria/approval; V6 says Classic needs 0 subscribers while the request flow gates on `minSubScriber` (default 1)/`minWatchTime`.
- SUBS-1 [High, requirement] `users.totalSubscribers` is **never written** (model default 0; grep finds no writer) but gates Creator VIP tiers (Silver ≥5,000, Gold ≥25,000, Platinum ≥100,000) and Creator Funding tiers (≥10,000): those tiers/features are unreachable. (monetisation uses a live `countDocuments` instead — inconsistent.)
- REV-1 [High, requirement] No code path settles creator **ad revenue**: `settleRevenue({sourceType:"adRevenue"})` and `getCreatorRevenueShare()` (rewardEngine.js:213) have no callers; the only creator income from views is the template's flat `earningPerHour` (₹2/h) in `createWatchHistory` (and that is defective, WH-1). Creator VIP passes (₹1,499–₹9,999 per year/₹449–₹1,499 per quarter) are sold on a 60–80 % ad-revenue share that is never computed or paid; the platform has no ingestion of real ad revenue per video/creator.
- PROMO-1 [High, requirement] Video Promotion plans (₹49–₹3,000, DOC-20260826-WA0214) are sold and activated (`fulfilVideoPromotion`, admin approve) but delivery is absent: `videos.isPromoted` is set and never read by any feed/ranking/impression code, impressions are never counted or capped, and expiry never clears the flag.
- AC-1 (repeat) Ad credits granted with Starter Pass and partner licences are never consumable (see findings-draft-4).
- GR-1 [High, CONFIRMED by code — test pending] `POST /client/grievance/file` is reachable without authentication (`optionalAppUser`) and a CRITICAL category (`ANTI_NATIONAL`, `HATE_SPEECH`, `CSAM`) with any `videoId` sets that video to `moderationStatus: pending_review` (grievance.controller.js:60-67) — one anonymous request hides any video from all public feeds (malicious takedown); no rate limit, no per-video dedupe, no reporter verification.
- MOD-1 [Medium] Copyright flag demonetises (`isMonetization:false`) but creator watch earnings only check the *owner's* `isMonetization` (watchHistory.controller.js:146-151) and never `moderation.isMonetizable(video)` (used only by unlock settlement) → flagged videos keep earning (spec: "token earning/coin monetization disabled").
- MOD-2 [Medium] Audio transcription (Whisper) for keyword screening is not implemented anywhere (worker/fingerprintWorker.js handles fingerprints only); `screenVideo` runs on title/description/hashtags at upload; uploads are published (`moderationStatus` default) before any transcript screening.
- NOT-1 [Low] `notification.getNotificationList` uses `$dateDiff`/`$$NOW`, unsupported by the shim → the "time ago" text is built from nulls (" hours ago").
- DASH-1 [Medium] Admin dashboard "total channels" counts the `channels` collection, which the code base never writes (channels are `users.isChannel`), so the card is 0/stale; all dashboard queries read whole collections and bucket by UTC date, not IST.
- ADM-2 [Low] `admin/video.deleteVideo` hard-deletes only the video document (no comments/likes/reports/watch-history/storage cleanup, unlike `admin/report.deleteVideoReport`).
- FRAUD-ADM-1 [Low] `admin/fraud.toggleUserRestriction` uses `user.save()` (full-document overwrite, D-03).
